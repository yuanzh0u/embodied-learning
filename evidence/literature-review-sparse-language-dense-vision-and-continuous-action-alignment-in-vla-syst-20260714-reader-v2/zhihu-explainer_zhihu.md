# 为什么“语言稀疏、动作连续、图像稠密”会让 VLA 对齐变难？

## TL;DR

因为三种信号承担的职责和时间尺度不同。语言通常只给出目标，图像每帧包含大量未必与任务相关的细节，动作却要以连续控制量在真实本体上及时执行。VLA 对齐不是把三种 token 放进同一个模型，而是打通四个接口：语言到阶段目标、图像到任务状态、抽象动作到连续控制，以及失败信号到纠正动作。

## 常见误区：把统一 token 当成真正对齐

图文模型可以判断“这张图是否对应这句话”。机器人还要回答：在连续变化的场景里，这句话要求哪个子任务；此刻哪些视觉变化与它有关；下一段动作应该多快、多远；换了控制器和本体后，动作是否仍有相同物理含义。

例如，“把杯子轻轻放到盘子里”只在语言层给出终点和方式约束。视觉负责定位杯盘并追踪接触，动作策略要把“轻轻”变成随杯重、速度和接触状态变化的连续控制。如果“轻轻”只被压成固定动作标记，语义听懂了，落地仍会错。

## 真实机制一：语言要落到动作可用的中间目标

长文本推理并不会自动改善控制。[ERVLA](https://arxiv.org/abs/2606.03784) 的大规模实验表明，有效的具身思维链需要落到末端执行器运动或图像空间轨迹等动作相关表示；把显式思维链直接作为自回归动作前缀，反而会积累误差。

[稠密具身 CoT](https://arxiv.org/abs/2606.30552) 则把任务进度、子任务和动作监督拉到更细粒度。两类工作共同指向一个中间层：语言不必逐帧描述所有动作，但必须在关键阶段给出能约束空间和控制的目标。

## 第二关：稠密视觉能否被压缩成任务状态

图像中的大多数像素与当前动作无关。背景纹理、远处移动和光照变化很稠密，真正决定动作的却可能只是目标物位置、可达区域、夹爪状态和接触关系。

[SSI-Policy](https://arxiv.org/abs/2606.26800) 用结构化场景接口把视觉信息整理成可供动作策略使用的状态。它代表一种重要思路：对齐不必让动作头直接理解全部像素，而是先形成与任务相关、可检查的中间表征。代价是检测、深度和结构化字段本身也可能出错，因此接口需要与端到端闭环一起评估。

## 第三关：动作 token 能否回到正确的连续控制

把动作离散化有利于自回归建模，却不会消除控制问题。[SA-VLA](https://arxiv.org/abs/2606.30113) 说明，固定动作 token 的解码仍受机器人状态和接触条件影响。同一个离散选择，在不同状态下可能需要不同速度、幅度或关节控制。

跨机器人时问题更明显。[SPACE](https://arxiv.org/abs/2606.24049) 指出，同一控制命令在不同本体、控制器和部署动力学下可能产生不同运动。它改用笛卡尔状态变化作为共享中间表示，再由动作适配器转换成机器人特定命令。共享的是“物理状态要怎样变化”，不是假定所有机器人的底层命令天然一致。

## 第四关：接触和失败能否进入纠正闭环

RGB 很难完整观察滑移、卡滞和接触力。如果训练数据只有成功动作，模型也很难学会失败后如何回到可行状态。[TACO](https://arxiv.org/abs/2607.02840) 用视频—力联合世界模型识别失败附近状态，并生成带纠正动作的想象片段。它补上的不是更多语义，而是视觉之外的物理反馈和恢复监督。

因此，对齐的终点不是让语言、视觉和动作共享一个损失，而是让任务意图在执行中不断接受真实结果校验。系统要逐步确认状态是否改变、接触是否安全、动作是否产生预期后果，以及失败后应从哪一步恢复。

## 一个可复用的诊断方法

可以按接口逐层替换。先给定正确的任务阶段，观察动作是否恢复；再给定真实空间状态，排除视觉结构化错误；最后把目标状态交给已验证的控制器，检查动作解码和本体适配。哪一步替换首次让闭环恢复，就优先修哪一层。

这比只看离线动作误差更有信息量。平均误差相近的两个模型，可能一个经常选错任务阶段，另一个只在接触瞬间幅度偏大；两者需要完全不同的数据和修复手段。

## 边界：接口更清楚，不代表系统一定更简单

阶段标签、结构化视觉和动作适配器能够降低单个模块的对齐负担，也会增加标注、标定和维护成本。单目深度可能漂移，阶段标签可能不准，适配器也会在新硬件上失配。评价一项改进时，需要同时报告真实闭环收益、延迟和新增故障点。

所以 VLA 的关键进展不应只概括为“模型更大”或“token 更统一”。更准确的说法是：系统正在学习用不同中间表示连接不同时间尺度，同时保留动作的物理含义和可验证性。

## 延伸阅读

- [ERVLA](https://arxiv.org/abs/2606.03784)：解释具身推理为何必须落到动作相关表示。
- [Dense Embodied Chain-of-Thought](https://arxiv.org/abs/2606.30552)：将任务进度、子任务与动作监督细粒度对齐。
- [SSI-Policy](https://arxiv.org/abs/2606.26800)：把稠密视觉整理成结构化场景接口。
- [SA-VLA](https://arxiv.org/abs/2606.30113)：分析状态相关的动作 token 解码问题。
- [SPACE](https://arxiv.org/abs/2606.24049)：用状态变化和适配器处理跨本体动作语义。
- [TACO](https://arxiv.org/abs/2607.02840)：让触觉、失败状态和纠正动作进入后训练闭环。
