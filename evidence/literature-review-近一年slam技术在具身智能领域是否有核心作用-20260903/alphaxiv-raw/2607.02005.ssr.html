A Stereo Visual SLAM System Using Object-Level Motion Estimation and Geometric Filtering Based on Cross Disparity

SK
Sujan Kumar DhaliBhaskar Dasgupta

Abstract

This paper presents OCD SLAM, a dynamic stereo visual SLAM framework that extends ORB-SLAM2 by jointly addressing dynamic objects and dynamic features in the scene. Usual visual SLAM systems operating in dynamic environments often fail in the presence of moving objects, due to the static-world assumption used in pose estimation and mapping. To address this predicament, we introduce a novel geometric approach based on the discrepancy between disparity and a newly proposed notion called ``cross disparity'', which exploits both temporal and stereo inconsistency to identify dynamic feature points. Complementary to this feature-level motion analysis, OCD SLAM integrates a 3D object detection module (SMOKE) with Kalman filter-based object tracking to perform object-level motion classification, enabling robust separation of static and dynamic scene elements for accurate pose estimation. The proposed approach has been evaluated on various sequences from the KITTI Odometry and KITTI Raw datasets. Results demonstrate that OCD SLAM achieves significant improvement in trajectory accuracy compared to ORB-SLAM2 and several state-of-the-art dynamic SLAM methods. Ablation studies further demonstrate the effectiveness of the cross disparity module in the KITTI Raw dataset and show that this method is able to detect dynamic features that are missed by the 3D object detection scheme alone.

AI Overview

Introduction to Dynamic SLAM Challenges

Simultaneous Localization and Mapping (SLAM) is a cornerstone technology for autonomous navigation, allowing robots and vehicles to map their surroundings while determining their own location within that map. Most established visual SLAM (vSLAM) systems, such as ORB-SLAM2, operate under the "static-world assumption." This assumption posits that the environment is entirely stationary, and any detected movement is treated as sensor noise or outlier data to be ignored.

However, real-world environments like city streets are rarely static. Moving cars, pedestrians, and cyclists can significantly disrupt traditional vSLAM systems. If a SLAM algorithm attempts to use features on a moving bus to calculate its own position, the estimated trajectory will drift, leading to catastrophic failure in localization and a corrupted map. Existing solutions generally fall into two categories: semantic-based methods that use deep learning to detect and remove dynamic objects, and geometric methods that use mathematical constraints to identify moving pixels.

Figure 1: The framework of OCD SLAM, illustrating the parallel threads for tracking, mapping, loop closing, and the integrated 3D object detection module.

This paper introduces OCD SLAM, a system designed specifically for highly dynamic outdoor environments. OCD SLAM addresses the limitations of previous methods by combining 3D object detection with a novel geometric filtering technique called "cross disparity." This dual-layer approach allows the system to distinguish between static and dynamic objects more reliably and even identify motion from objects the system was not specifically trained to recognize.

Integrating 3D Object Detection

A key feature of OCD SLAM is its dedicated 3D Object Detection thread, which runs in parallel with the standard tracking and mapping tasks. Many existing dynamic SLAM systems use 2D semantic segmentation (identifying pixels as "car" or "person"), but this often removes useful data. For example, a parked car is a perfectly valid stationary landmark for SLAM, but a 2D segmentation mask would simply label it "dynamic" and discard it.

OCD SLAM uses SMOKE (Single-Stage Monocular 3D Object Detection), a deep learning model, to estimate the 3D properties of objects from the camera's viewpoint. This includes:

  • The projected 3D keypoint (center) of the object.
  • The physical dimensions (height, width, and length).
  • The yaw angle ϕ\phiϕ, which represents the object's orientation.

Figure 2: Examples of 3D bounding boxes estimated by the SMOKE detector on the KITTI dataset.

By working in 3D, the system gains a better spatial understanding of the scene. Instead of treating every "car" as a moving object, OCD SLAM actively estimates the velocity of these objects to determine if they are truly moving or currently parked.

Refining Object Boundaries with Convex Hulls

Standard object detectors provide rectangular 2D bounding boxes. However, these rectangles often include "empty" space—parts of the background that do not belong to the object. If a SLAM system removes all features within such a rectangle, it inadvertently discards static background information that could have helped with localization.

Figure 3: Illustration of how traditional 2D bounding boxes (blue) capture background noise, whereas a convex hull (red) provides a tighter fit.

To solve this, the researchers project the eight 3D corner points of the estimated 3D bounding box back onto the 2D image plane. They then calculate a "convex hull"—the smallest convex polygon that contains all these points.

Figure 4: A detailed view of a convex hull tightly enclosing a vehicle, ensuring that background features are preserved for the SLAM system.

This geometric refinement ensures that only ORB features (keypoints used for tracking) that actually lie on the object are associated with it. Features outside the hull are correctly identified as background and used normally for pose estimation.

Velocity Estimation via Kalman Filtering

To decide whether a detected object is a threat to SLAM stability, the system must determine its motion state. OCD SLAM tracks objects across frames by matching their ORB descriptors, comparing their 3D locations, and ensuring their estimated volumes remain consistent.

Once an object is tracked, its velocity is estimated using a Linear Kalman Filter. This filter is necessary because raw 3D position measurements from a camera are often noisy; calculating velocity by simply subtracting positions between frames would result in "jittery" and inaccurate speed estimates.   • Static: The estimated speed is below a threshold (e.g., parked cars). These features are kept and given higher priority.
  • Dynamic: The estimated speed is above the threshold (e.g., driving cars). These features are discarded.
  • Unknown: Confidence in the velocity estimate is low. These features are excluded from critical optimization steps until their state is clarified.

Feature-Level Filtering with Cross Disparity

The most technically distinctive contribution of this work is the "cross disparity" geometric constraint. While deep learning is excellent at detecting known categories like "cars," it fails to recognize motion from unknown objects (like a moving construction crane or a tumbling box). Furthermore, detection models can miss partially occluded objects.

Performance on the KITTI Dataset

The system was evaluated using the KITTI dataset, a standard benchmark for autonomous driving. The researchers compared OCD SLAM against the baseline ORB-SLAM2 and several modern dynamic SLAM systems like DynaSLAM and AirDos.

The primary metric used is Absolute Trajectory Error (ATE), which measures the difference between the estimated path and the ground truth. In KITTI Sequence 01, which features high-speed highway driving with several moving vehicles, OCD SLAM reduced the ATE from 10.96m10.96m10.96m (ORB-SLAM2) to 8.68m8.68m8.68m.

Figure 6: Visualization of tracked objects with unique IDs and motion labels. Blue boxes represent static/parked cars, while red indicates dynamic motion.

In sequences like Sequence 07 (urban driving), OCD SLAM achieved an ATE of 0.46m0.46m0.46m, outperforming DynaSLAM (0.51m0.51m0.51m) and Wen et al. (0.55m0.55m0.55m). The results across both KITTI Odometry and KITTI Raw datasets indicate that the system is consistently more robust than its predecessors in the presence of traffic.

The Importance of the Hybrid Approach

To understand why the system works, the authors performed "ablation studies"—testing the system with certain parts turned off.

When using only SMOKE (3D detection), the system struggled with objects it wasn't trained for, like large buses or trucks, which are common in the KITTI Raw dataset. When using only Cross Disparity, the system was good at finding motion but sometimes misclassified static features as dynamic due to sensor noise, leading to a loss of useful tracking data.

Figure 7: Example of the system successfully filtering dynamic features on a moving bus (red points) while retaining static features on the background (green points).

The full OCD SLAM system (SMOKE + Cross Disparity) consistently produced the lowest errors. This proves that the two components are complementary: the 3D detector provides high-level semantic context (allowing the system to "know" a car is parked and should be used for tracking), while the cross disparity module provides a low-level geometric check that catches any motion missed by the AI.

Conclusion

OCD SLAM demonstrates a robust architecture for stereo visual SLAM in dynamic environments. By moving beyond simple 2D masks and adopting 3D object-level motion estimation combined with a cross-disparity geometric filter, the system achieves state-of-the-art accuracy on challenging real-world datasets.

While the system currently processes at roughly 12–1412\text{--}1412–14 frames per second—slightly slower than the 23–2523\text{--}2523–25 fps of the original ORB-SLAM2—it offers the reliability needed for autonomous vehicles to navigate through busy traffic without losing their way. Future developments could expand the object detection library to include a wider variety of vehicles and optimize the geometric calculations for even higher performance.
