# 综述工作流的三段结构：检索、阅读、写作的独立性与组合用法

> 定位：概念文档。说明综述工作流按"检索 → 阅读 → 写作"三段切分后，每一段**能否独立工作**、独立时**支持什么用法**、三段之间靠什么接合。不涉及代码细节与命令用法（工程入口见 `scripts/README.md`，决策背景见 [ADR 0003](adr/0003-consolidate-to-three-skills.md)）。

## 1. 三段各自回答一个问题

| 段 | 核心问题 | 输入 | 产出 | 质量责任 |
|---|---|---|---|---|
| 检索 | "这个领域里**该读哪些**论文？" | 主题、时间窗、检索策略、（可选）种子论文 | 候选池、筛选队列、覆盖度/饱和证明 | **覆盖面**：没有系统性漏读 |
| 阅读 | "这篇论文**到底说了什么**？" | 一篇论文的全文 | 证据事件（主张 + 立场 + 置信 + 可溯源锚点 + 逐字引文） | **真实性**：主张必须能在原文中定位 |
| 写作 | "这些证据合起来**对读者说明什么**？" | 一组证据事件 | 面向读者的成稿（论证组织、引用审计） | **论证与表达**：主张不越证据边界 |

三段是**单向**的：检索不写读者可读的文字，阅读不看主题的"大局"，写作不改变证据事实。单向性的意义在于每段的失败模式不同、可分别重试与复用。

## 2. 检索：可以独立，且天然是半成品交付物

**可以独立。** 检索的输入只有"主题 + 窗口 + 策略"，完全不感知下游。它产出的候选池与筛选队列本身就是可交付的中间品——一份带覆盖度/饱和自检的文献地图。

独立工作时的用法：

- **选题调研**：只跑检索，看候选规模、影响力排序、维度覆盖，回答"这个方向有什么、热点在哪"，不进入深读。
- **种子引文扩张**：以一篇已知论文为锚，沿其学术邻域（引用/被引）展开候选——这是与关键词检索并列的一条独立检索通道，适合"围绕某篇论文的综述"这类以论文为起点的任务。
- **文献地图维护**：候选池跨 run 持久存在，同一领域的后续综述可增量复用，不必每次从零检索。

边界：检索的结果**永远不是证据**。它的自检（候选地板、覆盖维度、饱和收敛）证明的是"没漏读"，证明不了"读过的都对"——真实性责任完全在下游。

## 3. 阅读：可以独立，这是整个结构的承重墙

**可以独立，而且"独立于任何一次综述"是刻意设计。** 阅读的输入是"一篇论文"，不是"一个综述主题"——单篇深读产出带审计的证据事件后进入公共论文池，此后**任何**综述、任何主题都能零成本复用这篇论文的阅读成果。深读是整个流程中最贵的环节，池化让它从"每次综述的内部步骤"变成"跨主题的公共资产"。

独立工作时的用法：

- **单篇速读**：对一篇感兴趣的论文产出速读卡，不关联任何综述。
- **单篇问答**：针对一篇论文做溯源可查的对话，同样不依赖综述上下文。
- **批量入池**：按书单/文献表批量深读建库，先存证据、后找用途。
- **补充深读**：某次综述证据不足时，单独为缺口论文补深读，再把事件喂回写作。

阅读自带**自校验闭环**：主张必须配原文定位与逐字引文，审计不过则事件不成立。因此它不信任上游——即使检索漏了或错排了队列，只要全文在手，阅读产出的证据依然可信。这使"阅读 + 写作"可以在**没有检索**的情况下组成完整工作流（见 §5）。

## 4. 写作：可以独立，但独立于"过程"、不独立于"证据"

**可以独立跑，前提是证据事件已在手。** 写作对"证据从哪来、哪次产"完全无感知：本 run 深读的、历史 run 池化的、引文图派生的，一视同仁。因此它可以脱离检索和阅读单独工作。

独立工作时的用法：

- **跨 run 综合**：不改证据，把多个历史 run 的事件按新问题重新组织成稿（仓库中"跨 run 综合专题"即此形态）。
- **换风格重写**：同一证据集面向不同读者重写（备忘录 / 社媒解释稿），检索与阅读零参与。
- **修订成稿**：审稿意见到来后只动论证与表达，证据层不动。
- **引文图派生综述**：以种子论文的引文图选篇、人工复核后直接成稿——选篇不走覆盖度门，是写作旁路检索质量契约的一种**显式声明**的例外形态。

约束：写作的独立性被**引用审计**封顶——成稿中每条可溯源主张必须落在已加载的证据集内，死锚点、超范围引用都会被门禁拦下。所以准确的表述是：写作独立于**过程**，但不独立于**证据**；它可以从既有证据出发自由工作，不能无中生有。

## 5. 组合矩阵：三段的在场与缺席

| 组合 | 形态 | 典型场景 |
|---|---|---|
| 只有检索 | 文献地图 | 选题调研、方向盘点、候选池储备 |
| 检索 + 阅读 | 证据库建设 | 不急于成稿，先建"读过的论文池"；领域数据集评估 |
| 阅读 + 写作 | 无检索综述 | 复用历史池/证据事件回答新问题；跨 run 综合 |
| 只有写作 | 成稿修订 | 换风格、改论证、响应审稿意见 |
| 只有阅读 | 单篇服务 | 速读卡、论文对话、按书单建库 |
| 三段全跑 | 完整综述 | systematic / scoping / rapid 三档强度的正式 run |

两个值得注意的不对称：

- **缺检索的组合（阅读+写作、只有写作）质量自洽**——因为阅读和写作各自带审计闭环，证据真实性与引用边界都有门禁保障。
- **缺阅读的组合（只有检索）产出永远停留在"候选"**——这是唯一没有质量闭环的形态，它的产出只能用于决策参考，绝不能被下游当作证据引用。

## 6. 为什么复杂度集中在检索

三段面对的**世界开放度**不同，决定了各自的工程形态：

- **检索面对开放世界**：查询措辞、检索源限流、引文网络规模、饱和判定、时间窗内的长尾——没有一个封闭边界可以"读完"。这是综述中最复杂、最需要编排固化的部分，也是唯一需要多轮迭代证明"可以停了"的部分。
- **阅读面对封闭输入**：一篇论文是有限、确定的文本，深读是可标准化的流程（骨架 → 定位校验 → 组装 → 审计），复杂度已被流程吸收，因此能做成可复用的池化单元。
- **写作面对封闭证据集**：证据事件在写作开始时已定，创作自由度在论证组织与表达层，质量由审计门兜底。

由此推出各段的**失败语义**也不同：检索失败（无法收敛或证据不足）是唯一允许整场提前停止的条件；单篇阅读失败只是池中缺一篇，不掏空证据基础；写作失败可重写，不动上游。**三段各自可独立重试、可独立复用、可独立缺席**——这是三段结构真正的工程收益。

## 7. 接合面的两条铁律

三段之间只交换两种东西，各有一条不可让渡的规则：

1. **检索 → 阅读：候选 ≠ 证据。** 筛选队列只是优先级建议；队列里的论文在深读审计通过之前，没有任何主张可以引用它。
2. **阅读 → 写作：成稿 ⊆ 证据集。** 成稿的每条可溯源主张必须能锚回已加载的证据事件；审计门是写作与事实之间最后、也是唯一的一道墙。
